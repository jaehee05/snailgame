# 🎰 미니게임

친구들끼리 **가상 코인**으로 즐기는 미니게임 셋. Next.js + Firestore, Vercel 배포용.

| 게임 | 회차 | 규칙 |
| --- | --- | --- |
| 🐌 달팽이 레이싱 | 68초 | 8마리 중 4마리가 출전. 단승 / 연승 / 복승 / 쌍승 / 삼쌍승 |
| 🎲 홀짝 | 30초 | 1~100 추첨. 홀·짝·대·소와 그 조합 |
| 📈 그래프 | 36초 | 배수가 오르다 터진다. 터지기 전에 인출 |

- 잔액은 세 게임이 공유한다
- 아이디 + 비밀번호 자체 로그인 (외부 인증 서비스 없음)
- 잔액·베팅·정산은 전부 서버에서 처리
- 관리자 페이지에서 게임 머니 지급 / 회수 / 비밀번호 초기화
- 커밋-리빌 방식으로 결과 조작 여부를 브라우저에서 직접 검증 가능

> 이 게임의 코인은 현금 가치가 없는 가상 코인입니다. 현금 환전이나 실제 도박 용도로 쓰라고
> 만든 게 아니며, 그런 기능은 들어 있지 않습니다.

## 어떻게 굴러가는가

회차 번호는 `floor(현재시각 / 회차길이)` 로 정해진다. 게임마다 회차 길이가 달라서
번호도 따로 매겨진다. 별도의 스케줄러나 크론이 없고, 서버·클라이언트
모두 시계만 보면 지금이 몇 회차의 어느 구간인지 알 수 있다.

회차마다 두 개의 시드가 있다.

| 시드 | 공개 시점 | 결정하는 것 |
| --- | --- | --- |
| `publicSeed` | 회차 시작과 동시에 | 달팽이 출전표와 배당처럼 미리 보여줄 것 |
| `secretSeed` | 베팅 마감 직후 | 경주 순위 / 추첨 숫자 / 터지는 배수 |

베팅 중에는 `secretSeed` 대신 그 SHA-256 해시(커밋)만 공개된다. 마감 후 원본 시드가 공개되면
브라우저가 직접 해시를 다시 계산해 커밋과 대조한다 (`components/Fairness.tsx`). 결과를 나중에
바꿔치기하면 이 검증이 바로 깨지므로, 운영자도 결과를 손댈 수 없다.

결과 계산은 전부 시드만 주어지면 결정론적이라, 서버와 모든 참가자의 화면이 같은 순간에
같은 것을 본다. 마감 후에는 브라우저가 시드로 직접 결과를 계산하므로 서버에 다시 묻지 않는다.

**그래프의 인출만은 예외다.** 지금 몇 배인지는 서버 시계로만 판단하고, 이미 터진 뒤의
요청은 거절한다. 브라우저 시각을 조작해도 소용이 없다.

배당은 `publicSeed` 로 만든 출전표를 900번 시뮬레이션해 적중 확률을 추정하고, 환급률(기본 90%)을
곱해서 만든다. 비공개 시드와는 무관하므로 배당표를 들여다봐도 결과를 알 수는 없다.

## 로그인

외부 인증 서비스를 쓰지 않고 직접 구현했다.

- 비밀번호는 `scrypt` 로 계정마다 다른 솔트를 써서 해싱해 저장한다 (원문은 저장하지 않는다)
- 세션은 HMAC-SHA256 으로 서명한 HttpOnly 쿠키 (30일). 서명이 어긋나거나 만료되면 거부된다
- 비밀번호를 잊었을 때는 관리자가 `/admin` 에서 초기화해 준다 (이메일 인증이 없다)

## 로컬 실행

```bash
npm install
cp .env.example .env.local   # 값 채우기
npm run dev
```

## Firebase 설정

1. [Firebase 콘솔](https://console.firebase.google.com/) → 프로젝트 `snailgame-b08e2`
2. **Firestore Database** 생성
3. **프로젝트 설정 → 서비스 계정 → 새 비공개 키 생성** 으로 JSON 다운로드
   → `.env.local` 의 `FIREBASE_SERVICE_ACCOUNT` 에 통째로 붙여넣기 (base64 도 가능)
4. **보안 규칙을 `firestore.rules` 내용으로 교체** ← 중요

Firebase Authentication 은 쓰지 않으므로 따로 설정할 게 없다.

### 보안 규칙을 꼭 잠글 것

테스트 모드로 만든 Firestore 는 **누구나 웹 API 키만 알면 컬렉션을 직접 읽고 쓸 수 있다.**
이 게임은 비밀번호 해시와 잔액을 Firestore 에 저장하므로, 그대로 두면 참가자가 브라우저에서
자기 잔액을 마음대로 고칠 수 있다. (게다가 테스트 모드는 30일 뒤 만료되어 앱이 멈춘다.)

`firestore.rules` 는 클라이언트의 모든 읽기/쓰기를 막는다. 이 게임의 데이터는 서버의
Admin SDK 로만 드나드는데 Admin SDK 는 보안 규칙을 우회하므로, 규칙을 전부 잠가도 게임은
정상 동작한다. 콘솔의 **Firestore → 규칙** 에 `firestore.rules` 내용을 붙여넣고 게시하면 된다.

## Vercel 배포

```bash
npx vercel        # 최초 1회, 프로젝트 연결
npx vercel --prod
```

환경변수는 Vercel 프로젝트 설정 → Environment Variables 에 등록한다.

| 변수 | 필수 | 설명 |
| --- | --- | --- |
| `FIREBASE_SERVICE_ACCOUNT` | ✅ | 서비스 계정 JSON (또는 base64) |
| `AUTH_SECRET` | ⚠️ | 세션 쿠키 서명 키. `openssl rand -hex 32`. **노출되면 남의 세션을 위조할 수 있다** |
| `ROUND_SECRET` | ⚠️ | 회차 시드 생성 키. `openssl rand -hex 32`. **노출되면 미래 회차 결과가 예측 가능해진다** |
| `ADMIN_NICKS` | | 관리자로 자동 승격할 아이디(쉼표 구분) |

## 관리자

`ADMIN_NICKS` 에 넣은 아이디, 또는 **가장 먼저 가입한 계정**이 관리자가 된다.
관리자는 `/admin` 에서 참가자 목록·잔액을 보고 코인을 지급하거나 회수할 수 있고,
권한 변경과 비밀번호 초기화도 여기서 한다. 모든 지급 내역은 `ledger` 컬렉션에 남는다.

## 구조

```
app/
  page.tsx            경주장 (메인)
  login/              로그인 · 회원가입
  admin/              관리자 (머니 지급)
  api/auth            가입 · 로그인 · 로그아웃 · 비밀번호 변경
  api/round           회차 정보 (?game=snail|oddeven|crash)
  api/me              내 상태 조회 + 밀린 회차 자동 정산
  api/bet             베팅 접수 (금액·배당 서버 검증)
  api/cashout         그래프 인출 (서버 시계로 배수 판정)
  api/admin           참가자 목록 · 코인 지급 · 권한 · 비밀번호 초기화
lib/
  config.ts           게임 공통 상수
  games/              게임별 규칙 (snail / oddeven / crash)
  prng.ts             시드 기반 결정론적 난수
  race.ts             달팽이 로스터 · 경주 시뮬레이션
  bets.ts             베팅 종류 · 배당 산출 · 적중 판정
  seeds.ts            회차 시드와 커밋 해시 (서버 전용)
  round.ts            게임별 회차 계산 + 배당 캐시
  auth-session.ts     비밀번호 해싱 · 세션 쿠키 서명
  db.ts               Firestore 데이터 계층 (계정 · 베팅 · 정산)
```

정산은 크론 없이, 사용자가 접속할 때 밀린 회차를 따라잡는 방식이다 (`settleUser`).
접속을 안 하고 있었더라도 다음에 들어오면 그동안의 회차가 순서대로 정산된다.
